## 一、包结构（对标 jotcash）

排布轴 = 离外部多远；越靠根部越通用，内层不得被外层反向依赖。

| 包 | 位置 | 职责 | 业务逻辑 | 对标 jotcash |
| --- | --- | --- | --- | --- |
| `model` | 根部 | 数据契约：配置、快照、全局视图、资源、告警记录、枚举 | 无 | `model` |
| `config` | 根部 | 配置加载热更（`util.ConfigService`）+ 监听地址/路径/阈值常量 | 无 | `config` + `config/handler.go` |
| `probe` | 根部 | 外部适配：GET 单个 URL，判定在线/失败，解析对端视图 | 无 | `exchange_rate` |
| `resource` | 根部 | 外部适配：采集本机 CPU/内存/磁盘/负载 | 无 | `exchange_rate` |
| `handler` | 根部 | 协议入口：ping、status、静态页 | 无 | `handler` |
| `static` | 根部 | 前端 embed | 无 | `static` |
| `corn` | 根部 | 周期触发入口 | 无 | `corn` |
| `service` | 内层 | 业务编排：一轮探测、判定、告警、看板数据组装 | 全部 | `service` |
| `service/view` | 内层 | 全局视图读写（内存状态仓库，带业务校验） | 全部 | `service/repo` |

- **不建 `alarm` 包**：`util.SendWxMsg` 已是适配层，再包一层只是改名转发，属过度拆分；文案组装带业务规则，归 `service`。
- **不建 `tool` 包**：暂无「带本系统规则的纯工具」，按「过早设计深层包 = 设计跑在理解前面」不预留。
- **不建 `service/<能力>/<实现>`**：探测只有 HTTP 一种、告警只有微信一种，无多实现需求。

## 二、实现顺序

1. `model` → 2. `config` → 3. `probe` / `resource`（可并行） → 4. `service/view` → 5. `service` → 6. `handler` / `corn` → 7. `static`

## 三、数据契约（`model`）

- `Config`：`urls []string`（唯一必配项），其余阈值走默认常量兜底
- `Snapshot`：一个实例的一份快照 —— `source`（身份键）、`time`（原始产生时间）、`probes map[url]bool`（本实例对各 URL 的收敛结论）、`resource`、`alarms map[url]Alarm`
- `View`：对外形态 —— `snapshots map[source]Snapshot`，即 status 接口响应体的 data
- `Resource`：CPU/内存/磁盘/负载 + 采集时间
- `Alarm`：`startTime`（事件起始）+ `lastSendTime`（上次发送）
- `Record`：本地探测明细（URL、时间、是否在线），只供看板状态条，**不进交换载荷**

## 四、关键技术决策

### 4.1 周期调度用守护协程池，不用 cron

- `util.NewDaemonSingleGoPool(ctx, name, 间隔, 任务)`：底层是 `ants.NewPool(1)`，任务返回后才休眠再投下一轮
- 天然满足「上一轮未结束不开新一轮」，不需要额外互斥
- 旧代码用 `robfig/cron` 每分钟硬触发，日志实证轮次重叠（`logid=...010800000928` 到 01:09:23 仍在跑，下一轮已开始）
- 代价：`corn` 包名不再有 cron，保留是因为它在本仓与 jotcash 里已是「周期触发入口」的固定词

### 4.2 探测必须自建 HTTP 客户端

- 不能用 `util.NewHttpClientReq`：包级客户端是 `CreateHttpClient(3s, []{1s,2s,2s}, nil, true)`，带 3 次重试 + 4xx 会 `SetHttpBan(3s)`
- 后果就是旧代码的病根：单个失败点耗约 17 秒、封禁期内同 URL 直接失败
- 改用 `util.CreateHttpClient(超时, nil, nil, true)`：`sleeps` 为 nil 则不装重试条件、不设封禁

### 4.3 身份键由接收方回填

- 功能第 6 条要求「身份键 = 交换来源 URL」，但自己的快照无法自报（配置里认不出哪个 URL 是自己）
- 方案：**产出方把自己的 `source` 留空，接收方按「我从哪个 URL 拿到的」回填**
- 转发时只回填空值，已有 `source` 的原样透传 → 零配置，且不需要「本机对外 URL」这个配置项

### 4.4 识别对端用内容不用外壳

- 不靠 URL 形态判断是不是实例，靠「响应体能否解析出合规 `View`」
- 解析要穿透 `util.NewHttpRespByErr` 的 `{code,msg,data}` 外壳
- 识别条件严格到不会误认领，宁可不认领

### 4.5 并发探测与单轮预算

- 单轮用 `context.WithTimeout(ctx, 单轮预算)`，预算内并发 GET 全部 URL
- 并发用 `sync.WaitGroup` + 带缓冲 channel 限流，不引新依赖
- 超预算未完成的 URL 本轮记为失败（二值，已无「不确定」）

### 4.6 合并与过期

- 按 `source` 为键，`time` 新者胜；转发只读不改 `time`
- 判定分母 = `time` 未过期的全部 `Snapshot`；对端全过期时分母只剩自己，自动退化为「按自己的结论算」
- 「连续多轮失败」在各实例本地收敛后再广播，交换载荷里只有收敛结论

### 4.7 锁收敛到一处

- 全局视图是唯一共享状态，锁收敛在 `service/view` 一把读写锁上
- 看板读取取读锁，合并/写入取写锁 —— 对应规范第六层并发语义镜像
- 每个导出函数配非导出纯逻辑实现，复合操作复用非导出版本，避免重入锁

### 4.8 镜像对（设计自检）

| 正向 | 反向 | 验收 |
| --- | --- | --- |
| 组装本实例 `View` 产出响应 | 解析对端响应为 `View` | 往返恒等测试 |
| 写入自己的结论 | 合并对端的结论 | 同一入口骨架，仅锁与来源不同 |
| 发离线告警 | 发恢复通知 | 共用同一判定函数，生产侧服从判定侧 |
| 看板读视图 | 探测写视图 | 读锁/写锁对称 |

## 二、与设计不同的地方

### 2.1 资源适配包叫 `machine` 不叫 `resource`

`resource/` 这个目录名已经被配置文件占用（`resource/survive_monitor.yaml`，与 jotcash 的 `resource/jotcash.yaml` 同构），Go 包不能同名。按「外部适配包按外部系统命名」，外部系统就是本机这台机器，取名 `machine`。

### 2.2 交换与看板拆成两个接口

- `/api/view` → `model.View`，纯交换载荷，配置里指向别的实例时填这个路径
- `/api/status` → `model.Status`（视图 + 本实例探测明细），只给前端

一个接口兼两用会让每轮交换都驮上整份明细，而明细本来就不进交换载荷。拆开之后两个接口各只干一件事。

### 2.3 快照多了一个 `Id` 字段

设计里身份键由接收方回填，零配置，但有个漏洞：本实例探自己的 `/api/view` 时，拿回来的视图里有自己那条，回填后会变成「我自己」的第二份副本，且时间更旧 —— 于是判定分母里同一份观测投两票，其中一票是旧的。离线刚发生时旧票还说「在线」，「全体一致」就凑不齐，告警被压住。

所以 `Snapshot` 加一个启动时生成的 `Id`，合并时丢掉 `Id` 等于自己的条目。仍然零配置，本实例也依旧不需要知道自己对外是哪个 URL。冒烟实测里 `合并全局视图 [len:0]` 就是这条在生效：探自己拿回一份视图，自己那条被正确丢掉。

### 2.4 `ParseView` 导出

它是 `GetView` 的镜像，验收标准是往返恒等，而往返测试要从包外发起才有意义（分别测两侧都通过、合起来对不上的情况是真实存在的）。导出之后 `handler` 的端到端测试可以直接拿交换接口的真实响应喂给它。

### 2.5 告警决策与投递拆开

`judgeAlarm` 只决定「该发什么、发完怎么写记录」，`alarmUrl` 负责发和写回。合在一起的话退避与恢复的判断必须连着微信凭据才能测。

## 三、关键实现要点

1. **周期调度**：`util.NewDaemonSingleGoPool`（底层 `ants.NewPool(1)`），任务返回后才休眠再投下一轮，「上一轮未结束不开新一轮」是白送的。已去掉 `robfig/cron`。
2. **单轮预算**：`context.WithTimeout` 掐断整轮；排队中还没拿到令牌的 URL 直接按失败落明细，不再白跑一次必然超时的请求。
3. **探测客户端**：`util.CreateHttpClient(超时, nil, nil, true)`，`sleeps` 传 nil 就不装重试条件、不设 4xx 封禁。按超时双检缓存。
4. **二值判定**：`statusCode` 落在 `(0, 500)` 算在线，其余（含超时、连接拒绝、DNS 失败）算失败；连续 `offline_round` 轮全失败才收敛成离线，明细不够轮数一律算在线。
5. **认领用内容不用外壳**：`ParseView` 要求响应体是本家外壳、业务码 200、`snapshots` 非空，三条缺一就当普通 URL。
6. **判定不对称**：离线要全部有新鲜结论的实例一致，恢复只要任一实例说在线。对端全过期时分母只剩自己，自动退化成「按自己的结论算」，不需要单独规则。
7. **重试靠轮询**：离线且没发过就地发，**发送成功才写记录**；失败则下一轮重新判定重新发。
8. **资源告警只管本机**：资源是各实例自己采的，也就只有自己有资格判它持续超了几轮；别的机器超没超由它自己那个实例告警。
9. **锁只有一把**：全局视图是唯一共享状态，锁收敛在 `service/view`。导出函数加锁、非导出纯逻辑不碰锁，复合操作（`GetStatus`）复用非导出实现而不重入锁。

## 五、遗留与风险

1. **告警通道凭据未注入时是静默失败的**。你已决定不做通道自检，这里只记录现象：没有 `wx_app_id`/`wx_secret` 时每轮都会 `发送服务告警，异常`，日志是 Error/Warn 级别，但没有任何对外可见的信号。冒烟日志就是这个样子。

# 对话3：响应解析不再复用 util

## 问题

`probe.ParseView` 原来用 `util.JsonData2Struct` 解析响应体，而那个函数解析失败会把整个响应体打进日志（`go_common/util/json.go` 里 `logrus.WithFields(logrus.Fields{"data": string(data), ...}).Error("反序列化json异常")`）。

本服务对**每个** URL 的响应都要试着认领一次全局视图，而绝大多数被探测的 URL 返回的本来就是网页 —— 于是每轮、每个 URL 都会往日志里刷一整页 HTML。13 个探测点、每分钟一轮，日志很快就被灌满。

对话2 的冒烟日志里已经能看到这个现象：`[data:<html>hello</html>] [err:readObjectStart...] 反序列化json异常`。

## 改动

`probe/probe.go` 改用标准库 `encoding/json` 的 `json.Unmarshal` 直接解析，不走 `util`，解析失败静默返回「不认领」。

选型依据：

- 解析失败是**预期之中**的情况（普通 URL 本来就不该被认领），按日志级别判据它连 Warn 都不该是，更不该是 Error
- 外部适配包用标准库 json 解析外部响应，本就是项目既有做法：jotcash 的 `exchange_rate/exchange_rate.go` 用的就是 `encoding/json`，`json-iterator` 在它的 go.mod 里也只是 indirect
- 不认领这件事已经由 `探测URL，响应` 这条 Info 日志覆盖（只带 url 和状态码），不需要再补日志

往返恒等测试照旧通过 —— 产出侧走 `util.JsonStruct2Data`（json-iterator），认领侧走标准库，这条测试顺带把两个序列化实现的互通性也钉住了。

## 验证

冒烟：起一个假服务，`/page.html` 返回 7KB 多的 HTML（内含标记串 `LONGPAGEMARKER`），`/api/weird` 返回**本家外壳但 data 不是视图**的 JSON（`{"code":200,"data":{"ip":...,"sn":...,"ts":...}}`），再加上自己的 `/api/view`，跑 8 轮：

| 检查项 | 结果 |
| --- | --- |
| 日志里 `LONGPAGEMARKER` 出现次数 | 0 |
| 日志里 `反序列化json异常` 出现次数 | 0 |
| 日志里 `DOCTYPE` 出现次数 | 0 |
| HTML 页面 | `探测URL，响应 [statusCode:200]`，未认领，只有 url 和状态码 |
| 本家外壳但 data 非视图 | 同样未认领、同样无日志噪音 —— 这是最容易误认领的一类，解析得通但 `snapshots` 为空，被第二道条件挡掉 |
| 自己的 `/api/view` | `探测URL，解析到全局视图 [len:1]` |

每个 URL 每轮恰好一行日志，不带任何响应体内容。
